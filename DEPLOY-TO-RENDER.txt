HEALTHCONNECT NIGERIA — BACKEND CONNECTION SETUP
================================================

This project is prepared for a Render Node.js backend and MongoDB Atlas.
The frontend will NOT connect to the database directly. It calls the API.

IMPORTANT LIMITATION
-------------------
The website is not live-connected until you deploy the backend and set its
MONGODB_URI. I cannot log in to your Render/Atlas accounts or deploy to them
from this ZIP. This folder contains the code and configuration to do that.

1) MONGODB ATLAS
----------------
- Keep your existing cluster; do not delete the old healthcare database.
- In Atlas, create a NEW database user for this app if possible.
- Use a separate database name in the connection string, e.g. healthconnect_new.
  Example format only:
  mongodb+srv://DB_USER:DB_PASSWORD@YOUR_CLUSTER.mongodb.net/healthconnect_new
- In Atlas Network Access, allow the hosting provider to reach the cluster.
  For a quick Render test, some people use 0.0.0.0/0; this exposes the database
  endpoint to all IPs, so use a strong unique DB password and least-privilege
  database user, and tighten network access if your plan/setup supports it.
- Never put this URI in frontend files or commit it to GitHub.

2) DEPLOY BACKEND TO RENDER (FREE TIER MAY SLEEP)
-------------------------------------------------
- Push the healthconnect-project folder to a GitHub repository.
- In Render choose New + > Blueprint and select that repository; Render reads
  render.yaml. Alternatively create a Web Service with Root Directory `backend`,
  Build Command `npm install`, Start Command `npm start`.
- In Render > service > Environment set MONGODB_URI to your Atlas connection
  string. Set JWT_SECRET to a long random secret if it was not generated by the
  Blueprint. Keep secrets only in Render Environment, not in source code.
- Set CLIENT_ORIGIN to your actual frontend origin, for example
  https://lawrenceprecious.github.io
- Deploy and open https://YOUR-RENDER-SERVICE.onrender.com/api/health.
  It should return JSON with status "ok".

3) CONNECT FRONTEND TO RENDER
-----------------------------
- Open js/api-config.js.
- Replace https://YOUR-RENDER-SERVICE.onrender.com with your actual Render
  service URL (no trailing slash), then commit/push the updated frontend.
- If using GitHub Pages, publish the contents of healthconnect-project as the
  site files. Do not publish backend secrets or a .env file.

4) TEST
-------
- Open register.html and create a test account with a password of at least
  10 characters. The backend hashes passwords before saving them.
- Sign out/clear hc-token and test login.html.
- A booking can only be submitted by a signed-in user and only to a verified
  facility returned by GET /api/facilities. New facilities are unverified by
  default, so an administrator review workflow is still needed before real
  appointment bookings can succeed.

5) HEALTHCARE SAFETY
--------------------
This project is still a prototype, not ready for real patient/medical data.
Before production use, complete role-specific authorization, admin provisioning
and facility verification, account recovery, privacy/legal review, backups,
monitoring, security testing, and clinical/provider verification. Do not use
real patient information during initial testing.


MONGODB ATLAS CONNECTION FOR THIS PROJECT
Use the MONGODB_URI environment variable in Render. The .env.example file contains a TEMPLATE using your Atlas cluster and the separate database name `healthconnect_new`. Replace <DB_PASSWORD> with your MongoDB database user's password only inside Render's Environment Variables. Do not commit a real password to GitHub or put it in this ZIP. In Atlas Network Access, make sure the deployed backend is allowed to connect. Keep the old healthcare database unchanged.
